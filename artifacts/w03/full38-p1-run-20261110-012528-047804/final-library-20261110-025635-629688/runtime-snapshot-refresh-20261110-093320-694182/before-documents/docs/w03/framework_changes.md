# W03 课程运行框架改动说明

核对日期：2026-11-10。基线为课程原始 fde-student-w03-0.1.0-c16 工程。这里的“六个文件”是四个 Python 文件（其中两个新增）与两份产品提示词，不是六个彼此独立的框架缺陷。

## 为什么修改运行框架

构建 Skill 决定生成什么指标、SQL、单位和查询策略；运行框架负责将用户问题转换为意图、调用查询、组织回答。大枚举重复进入模型输入、外层工具调用补年份、结果展示换算和口径解释，发生在指标库生成之后。仅修改构建 Skill 不能控制这些运行环节，因此需要在对应层补充处理。

其中一部分属于课程通用框架在本作业规模和交互要求下的能力缺口，另一部分是青禾指标的展示适配。不能把所有客户特定规则都称为通用框架错误；业务资格及统计公式的依据仍来自业务模型、材料和指标定义。

## 六个文件逐项说明

### 1. platform/fde_product/metrics/intent_context.py（新增）

- 问题及归属：原调用把完整非时间枚举放进 filter_values，同时 available_dimensions 又包含这些值。规模集的账户等高基数枚举会扩大模型输入，这是运行时上下文组织问题。
- 修改：小枚举完整保留；超过默认128个值时，从完整本地枚举精确匹配当前问题及近期历史，优先当前问题，最多提供128个匹配值。另传总量、完整性和截断标记，避免将子集解释为全集。编号匹配检查边界，避免把 M001 当成 M0010。
- 不改时：模型仍接收重复的大量枚举，输入体积随数据规模增长，增加上下文和请求负担。该影响由代码路径可直接解释；本说明不虚构每次必然超时或未经测量的提速比例。
- 边界：只缩减模型输入；执行层仍使用完整本地值校验，没有扩展可筛选范围。

### 2. platform/fde_product/metrics/answer_display_facts.py（新增）

- 问题及归属：数值查询正确，文字仍可能把订单数写成账户数、将金额换错数量级、混淆零与未定义。属于结果展示层，不能靠改正确的SQL解决。
- 修改：从真实结果生成确定性的显示值与单位，用 Decimal 处理金额和比例换算；按指标区分单、账户、门店及件；保留分组、零和null，并拒绝非有限数等非法展示输入。
- 不改时：只给模型原始结果与文字换算要求，单位识别和换算仍主要依赖生成回答，缺少可直接引用的代码计算展示事实；不表示每条回答必然错误。
- 边界：计数对象映射包含本作业指标ID，属于客户适配，不是普适单位推断。展示事实不独立验证SQL，也不证明业务规则已经确认。

### 3. platform/fde_product/metrics/agent.py（修改）

- 问题及归属：辅助模块必须接入实际问数流程；只把文件放进工程，模型不会自动使用。
- 修改：意图调用前调用 prepare_intent_context，记录 intent-context-summary.json，并传入枚举元信息；查询成功后传入 build_answer_display_facts 生成的展示事实。
- 不改时：新增两个模块不会被该问数链调用，大枚举仍按原方式进入输入，回答模型也拿不到展示事实。
- 边界：仍调用原 query_worker 执行查询，没有改写查询结果或绕过执行校验。

### 4. platform/fde_product/metrics/integration.py（修改）

- 问题及归属：外层聊天Agent在调用 query_metrics 前可能改写问题。曾发现只有月份的问句被补成年份；内层即使正确识别“有年份的请求”，也无法恢复已丢失的原始歧义。
- 修改：外层提示要求忠实传递用户问题；时间补充只能来自用户明确提供或确认的上下文。助手旧回答、SQL、工具结果的年份不能当作用户确认；概念或因果问题不擅自扩写为索取数字。
- 不改时：内层缺年澄清规则可能被外层改写绕过；把错误补年后的查询结果视为正确理解用户会掩盖入口问题。
- 验证边界：历史新会话年份澄清证据保留在模型变更记录中；本轮正式库自然语言回归测试指标问数链，并不等于已经切换并复测外层聊天绑定。

### 5. product/w03_intent_prompt.txt（修改）

- 问题及归属：结构上可关联的维度不等于所选指标允许使用的维度；模型还可能增查指标、丢掉合法筛选或默认年份。这些是意图生成和限制解释问题。
- 修改：明确 query_policy 与 constraints 优先；完整自然月指标的筛选、分组及多月约束；解释精简枚举的完整性；区分格式要求与指标请求；合法零分母仍可查询；年份必须来自有效用户上下文，明确相对时间按参考日解释。
- 不改时：模型可能建议同样被禁止的替代分组、擅自扩大查询或补年；即使执行层拒绝，用户得到的建议或意图仍可能不忠实。
- 边界：提示不能代替执行层校验，也不能新增业务能力。拒答、澄清与执行成功分别验证。

### 6. product/w03_answer_prompt.txt（修改）

- 问题及归属：已执行结果正确不保证解释正确。历史展示问题及本轮总部适用性说明遗漏、首单排序解释不完整、付费复购率套用普通复购率公式，都发生在回答生成环节。
- 修改：使用代码展示事实和本轮 definitions，保留用户指定单位与零/null；首单按全覆盖期的日期、同日订单号确定再筛窗口；区分普通和付费复购率的完整分子分母，以及付费订单均额；当实际定义标注P1时，明确总部适用性待书面确认。
- 不改时：修复前的真实回答已经显示上述解释缺陷；结构化数值通过仍可能向读者传达错误公式或确认状态。
- 边界：文字遵循本轮定义，不改变SQL、数值或业务效力；模型仍需实际回答核查，不能因提示写入就判定修复成功。
