优先整理访谈者列出的 focus_questions 相关陈述，并保留理解这些陈述所需的背景。
区分客户对现状的说法、个人观点和目标、尚待核实的问题。一个条目尽量只表达一项可核对的主张。
同一个术语在不同角色、时间或范围下可能含义不同，保留原文限定，不自行统一。
若原文只提出问题而没有答案，不把问题改写成已经存在的业务规则。

【青禾提取方法 v1】
1. 一条候选尽量只表达一项可核对的主张。客户期望、现行做法、
   人工确认条件和授权声明性质不同时，分别提取并各自保留来源。
2. 区分访谈者的提问或总结与受访者明确确认的内容。
   同一会议存在后续纠正时，保留纠正后的含义及对应来源，
   不将被纠正的假设继续写成客户事实。
3. 提取职责时保留对象和环节：业务范围、系统统计口径、
   门店执行、核实协调、最终决定不能混为同一种权限。
   一位角色描述另一位角色的职责，不等于对方已确认。
4. 保留规则的触发条件、处理动作与适用范围。
   “确认前不执行”不能反推出“确认后允许自动执行”；
   明确未授权的动作继续保留为权限限制。
5. 区分角色表达的需求、个人感受、说明性例子和实际发生的事件。
   不把需求写成已实现能力，不把例子写成旧项目事实，
   不将角色要求升级为公司正式制度。
6. 具体字段、筛选阈值、记录载体、决定人或效果未明确时保留未知，
   不用常识补齐。来源必须支持该条主张，引用保持原文。
